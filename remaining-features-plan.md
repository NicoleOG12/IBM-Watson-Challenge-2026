### Sub-Task D — Question Matching Fallback (Saved Query Lookup)

**Status**: [ ] pending

**Intent**
Before calling watsonx.ai, check whether the user's question matches an existing saved query
(keyword token overlap ≥ 50%). If a match is found above threshold, return the saved SQL
directly inside `QueryResponse` with a `matched_query` field so the frontend can offer the
user a choice: "reuse this query" or "generate fresh". If no match, proceed with watsonx as
normal. Also expose as a standalone `GET /api/v1/queries/match?q=` endpoint.

**Expected Outcomes**
- New `services/query_matching_service.py` with `find_matching_query(question, user_id) -> SavedQuery | None`
  - Tokenizes both strings (lowercase, remove stopwords), computes overlap ratio
  - Returns the best match above 0.5 threshold, or None
- `QueryResponse` gains an optional `matched_query: SavedQuery | None` field
- `query_service.py` calls `find_matching_query()` before Step 4 (before watsonx call)
  - If match found: use the saved SQL directly, skip watsonx, mark `matched_query` in response
  - If no match: proceed normally
- New `GET /api/v1/queries/match?q=&user_id=` endpoint in `saved_queries_controller.py`

**Todo List**
1. Create `services/query_matching_service.py` with `find_matching_query()` using token overlap
2. Add `matched_query: Optional[SavedQuery] = None` to `QueryResponse` in `models/query.py`
3. In `query_service.py`, before Step 4: call `find_matching_query()` and short-circuit watsonx if match found
4. Add `GET /queries/match` route to `controllers/saved_queries_controller.py`

**Relevant Context**
- `watson-challenge-2026/backend/app/services/saved_queries_service.py` — `get_saved_queries()` to query the store
- `watson-challenge-2026/backend/app/models/saved_query.py` — `SavedQuery` model
- `watson-challenge-2026/backend/app/services/query_service.py` — Step 4 entry point
- `watson-challenge-2026/backend/app/models/query.py` — `QueryResponse`
